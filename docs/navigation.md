# 全面屏手势与上滑解锁

文档核对日期：2026-10-25。项目总体状态见 [README](../README.md)。

## 用户要求与当前解释

用户要求“全局采用全面屏，上滑解锁”。当前按系统级全面屏手势导航解释，隐藏底部传统三键导航，保留正常状态栏，不默认强制所有应用进入隐藏状态栏的沉浸模式。

## 目标行为

- 用户补充希望提供密码、指纹、面容解锁。密码作为必需能力；小米 4 LTE 没有内置指纹传感器，无法通过 ROM 实现真实指纹解锁，不添加假功能入口。
- 面容解锁列为待评估功能：仅可研究前置摄像头的 2D 本地识别，需验证相机适配、算法、许可、性能、抗照片攻击和锁屏集成，不能宣称已支持或等同安全硬件面容认证。
- 生物识别（若后续实现）必须先设置备用密码；重启后首次解锁、强制认证和失败锁定时使用密码。未验证的 2D 面容不得用于支付或作为强生物识别凭据。

- 全系统默认手势导航：底部上滑返回桌面，上滑停留进入最近任务，两侧边缘内滑返回。
- 锁屏上滑解锁；若启用 PIN、密码或图案，上滑进入凭据验证，不绕过验证。
- 未设置安全凭据时，上滑进入桌面；不因“上滑解锁”要求自动取消用户设置的安全锁。
- 横屏应用仍使用相应方向的系统手势区域，普通页面继续默认竖屏。
- 处理输入法、全屏视频、游戏、权限弹窗、首次引导和紧急呼叫的导航与触摸冲突。
- 小米 4 的实体/电容导航键需核对 keylayout 与背光控制；目标是避免与全面屏手势重复响应，不在未核对设备树时直接删除按键映射。电源和音量键保留。

## 集成要求

- 接入 Android 10 的手势导航、SystemUI 和支持最近任务集成的 Launcher/Quickstep；不能仅隐藏导航栏而失去返回/主页操作。
- 独立设计的 bestOS Launcher 需支持相应系统集成，具体实现与设备底座一起验证。
- 不全局强行设置沉浸标志；全面屏手势与隐藏状态栏是独立行为。

## 当前状态

只有需求规格，尚未修改 SystemUI、Launcher、锁屏或设备按键配置。尚无实机手势和解锁测试。
