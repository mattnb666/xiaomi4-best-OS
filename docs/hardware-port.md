# 小米 4 LTE 硬件适配与 MiFlash 构建

## 交付范围

bestOS 必须包含可用的小米 4 LTE 硬件适配、可重现的内核构建和匹配分区的 MiFlash 镜像；只有界面 APK 或产品资源覆盖不构成交付。

## 原厂包的用途

获取匹配实际 LTE 变种、来源可追溯的原厂 fastboot 线刷包，记录 SHA-256。先只读检查归档和刷写脚本，再核对 boot、分区表、固件及系统文件，不能直接运行原包脚本。

原厂镜像可能提供专有 HAL、GPU/相机库、无线固件等材料，但不等同于内核源码。旧 MIUI 文件须检查 ABI、链接依赖和 Android 10 接口适配，不能原样替换后宣称支持 Android 10。原厂 boot 也不能替代 bestOS 自己构建的 boot。

## 适配矩阵

| 子系统 | 需要核对和实现 | 验收 |
| --- | --- | --- |
| 屏幕/触摸 | 面板与触控驱动、设备树、电源时序、显示 HAL、合成与亮度 | 正常显示、触摸坐标、亮度、休眠唤醒 |
| 前后摄像头 | 传感器驱动、ISP/相机 HAL、专有库和配置、权限策略 | 前后摄拍照、录像、对焦、闪光灯及后台资源释放 |
| 处理器/GPU | 对应 SoC 内核支持、调度/频率、GPU 驱动与用户态库、温控 | 硬件加速、负载稳定、温控及待机 |
| 无线通信 | RIL、基带兼容、APN、音频路由、Wi-Fi/蓝牙驱动与固件 | 通话、短信、LTE、Wi-Fi、蓝牙音频 |
| 其他硬件 | 音频、传感器、充电、电池、按键、USB | 功能回归及重启验证 |
| 内核与启动 | 固定源码提交、defconfig、工具链、设备树、ramdisk/init、SELinux | 可重复编译、启动日志、数据挂载与加密 |

优先适配已有合法来源的驱动和源码，在缺失或不兼容处修改；不承诺从零重写闭源相机或 GPU 驱动。

## 构建顺序

1. 读取实机产品标识、现有内核及分区信息，核对可信原厂包。
2. 固定 AOSP Android 10、设备树、内核及专有文件来源，记录依赖和许可。
3. 准备 Linux 编译环境，先构建无 root 的最小系统并实测硬件。
4. 加入 bestOS 定制及应用，再用指定 Alpha 修补同次构建的 boot 并验证。
5. 按真实分区容量检查展开镜像；3 GB 是产品体积目标，不能覆盖分区大小限制。
6. 根据验证后的分区布局制作 MiFlash 脚本，明确数据清除行为，不重新锁定引导程序；在 Windows MiFlash 上完整试刷并验证恢复路径。

## 当前缺口

本项目尚无原厂线刷包、实际分区记录、完整 AOSP、匹配内核源码和工具链，也尚无硬件编译或测试结果。用户 Windows 电脑与当前 Mac 是不同环境，不能假定可直接远程运行 Windows 命令。
